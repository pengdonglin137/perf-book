# 优化内存访问 {#sec:MemBound}

现代计算机仍然基于经典的冯·诺依曼架构构建，该架构将 CPU、内存和输入/输出单元解耦。如今，内存操作（加载和存储）占性能瓶颈和功耗的最大部分。我们从这个类别开始也就不足为奇了。

内存层次结构性能至关重要的说法可以通过@fig:CpuMemGap 来说明。它显示了内存和处理器之间性能差距的增长。垂直轴是对数刻度，显示了 CPU-DRAM 性能差距的增长。内存基线是 1980 年 64 KB DRAM 芯片的内存访问延迟。典型的 DRAM 性能改进为每年 7%，而 CPU 享受每年 20-50% 的改进。根据这张图，处理器性能已经趋于平稳，但即便如此，性能差距仍然存在。[@Hennessy]

![内存和处理器之间的性能差距。*© 来源：[@Hennessy]。*](../../img/memory-access-opts/ProcessorMemoryGap.png){#fig:CpuMemGap width=90%}

变量可以在几个时钟周期内从最小的 L1 缓存中获取，但如果它不在 CPU 缓存中，从 DRAM 获取变量可能需要超过三百个时钟周期。从 CPU 的角度来看，最后一级缓存未命中感觉像是*非常长*的时间，特别是如果处理器在此期间没有做任何有用的工作。当系统被以非常高的速率访问内存的线程高度加载，并且没有可用的内存带宽来及时满足所有加载和存储时，执行线程也可能被饿死。

当应用程序执行大量内存访问并花费大量时间等待它们完成时，这样的应用程序被描述为受内存限制。这意味着为了进一步提高其性能，我们可能需要改进访问内存的方式、减少此类访问的数量，或升级内存子系统本身。

在 TMA 方法中，`Memory Bound` 指标估计 CPU 流水线因加载或存储指令需求而可能停顿的槽位比例。解决此类性能问题的第一步是定位导致高 `Memory Bound` 指标的内存访问（参见 [@sec:secTMA_Intel]）。一旦识别出有问题的内存访问问题，可以应用几种优化策略。在本章中，我们将讨论改善内存访问模式的技术。
