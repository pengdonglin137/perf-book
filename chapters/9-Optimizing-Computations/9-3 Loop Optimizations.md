## 循环优化 {#sec:LoopOpts}

循环是几乎所有高性能程序的核心。由于循环代表执行大量次数的代码，它们占执行时间的大部分。在这个关键代码片段中的微小变化可能对程序的性能产生很大影响。这就是为什么仔细分析程序中热循环的性能并了解可能的改进方法如此重要。

在本节中，我们将研究解决上述类型瓶颈的最著名的循环优化。我们首先讨论低级优化，在 [@sec:LowLevelLoopOpts] 中，这些优化只在单个循环内移动代码。接下来，在 [@sec:LoopOptsHighLevel] 中，我们将研究重构循环的高级优化，这通常会影响多个循环。注意，我在这里介绍的内容不是所有已知循环转换的完整列表。有关下面讨论的每个转换的更详细信息，读者可以参考 [@EngineeringACompilerBook] 和 [@OptimizingCompilersForModernArchs]。

### 低级优化。{#sec:LowLevelLoopOpts}

让我们从转换单个循环内代码的简单循环优化开始：循环不变代码移动、循环展开、循环强度折减和循环开关。通常，编译器擅长进行此类转换；但是，仍然存在编译器可能需要开发人员支持的情况。我们将在后续章节中讨论这一点。

**循环不变代码移动（LICM）**：值在循环的迭代中从不改变的表达式称为*循环不变*。由于其值在循环迭代中不会改变，我们可以将循环不变表达式移到循环外。我们通过将结果存储在临时变量中并在循环内使用它来做到这一点（参见 [@lst:LICM]）。[^17] 如今，所有优秀的编译器在大多数情况下都能成功执行 LICM。

Listing: 循环不变代码移动

~~~~ {#lst:LICM .cpp}
for (int i = 0; i < N; ++i)             for (int i = 0; i < N; ++i) {
  for (int j = 0; j < N; ++j)    =>       auto temp = c[i];
    a[j] = b[j] * c[i];                   for (int j = 0; j < N; ++j)
                                            a[j] = b[j] * temp;
                                        }
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**循环展开**：_归纳变量_是循环中的变量，其值是循环迭代次数的函数。例如，`v = f(i)`，其中 `i` 是迭代次数。我们不是在每次迭代时修改归纳变量，而是展开循环并为归纳变量的每次增量执行多次迭代（参见 [@lst:Unrol]）。

Listing: 循环展开

~~~~ {#lst:Unrol .cpp}
                                        int i = 0;
for (int i = 0; i < N; ++i)             for (; i+1 < N; i+=2) {
  a[i] = b[i] * c[i];          =>         a[i]   = b[i]   * c[i];
                                          a[i+1] = b[i+1] * c[i+1];
                                        }
                                        // 余数（当 N 为奇数时）
                                        for (; i < N; ++i)
                                          a[i] = b[i] * c[i];
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

循环展开的主要好处是每次迭代执行更多计算。在每次迭代结束时，索引值必须递增并测试，然后如果它有更多迭代要处理，我们就返回循环顶部。这项工作通常称为"循环开销"或"循环税"，可以通过循环展开来减少。例如，通过将 [@lst:Unrol] 中的循环展开 2 倍，我们将执行的比较和分支指令的数量减少 2 倍。

我不推荐手动展开循环，除非你需要打破循环携带的依赖，如 [@lst:DepChain] 所示。首先，因为编译器非常擅长自动完成此操作，通常可以选择最优的展开因子。第二个原因是处理器具有"嵌入式展开器"，这要归功于其乱序推测执行引擎（参见 [@sec:uarch]）。当处理器等待第一次迭代的长延迟指令完成（例如加载、除法、微编码指令、长依赖链）时，它将推测地开始执行第二次迭代的指令，并且只等待循环携带的依赖。这跨越了多个迭代，有效地在指令重排序缓冲区（ROB）中展开了循环。第三个原因是展开过多可能由于代码膨胀而导致负面后果。

**循环强度折减（LSR）**：用更便宜的指令替换昂贵的指令。这种转换可以应用于所有使用归纳变量的表达式。强度折减通常应用于数组索引。编译器通过分析变量的值在循环迭代中的演变来执行 LSR。在 LLVM 中，它被称为标量演化（SCEV）。在 [@lst:LSR] 中，编译器相对容易证明内存位置 `b[i*10]` 是循环迭代次数 `i` 的线性函数，因此它可以用更便宜的加法替换昂贵的乘法。

Listing: 循环强度折减

~~~~ {#lst:LSR .cpp}
for (int i = 0; i < N; ++i)             int j = 0;
  a[i] = b[i * 10] * c[i];      =>      for (int i = 0; i < N; ++i) {
                                          a[i] = b[j] * c[i];
                                          j += 10;
                                        }
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**循环开关（Loop Unswitching）**：如果循环内部有一个条件语句且它是不变的，我们可以将其移到循环外部。我们通过复制循环体并将其放置在条件语句的 `if` 和 `else` 子句中的每个版本中来做到这一点（参见 [@lst:Unswitch]）。虽然循环开关可能会使编写的代码量加倍，但这些新循环中的每一个现在都可以单独优化。

Listing: 循环开关

~~~~ {#lst:Unswitch .cpp}
for (i = 0; i < N; i++) {               if (c)
  a[i] += b[i];                           for (i = 0; i < N; i++) {
  if (c)                       =>           a[i] += b[i];
    b[i] = 0;                               b[i] = 0;
}                                         }
                                        else
                                          for (i = 0; i < N; i++) {
                                            a[i] += b[i];
                                          }
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

### 高级优化。{#sec:LoopOptsHighLevel}

高级循环转换改变循环的结构，通常影响多个嵌套循环。在本节中，我们将研究循环交换、循环分块（Tiling）、循环融合和分布（Fission），以及循环展开并压缩（Unroll and Jam）。这组转换旨在改善内存访问并消除内存带宽和内存延迟瓶颈。从编译器的角度来看，证明这种转换的合法性并论证其性能收益是非常困难的。从这个意义上说，开发人员处于更有利的位置，因为他们只需要关心其特定代码片段中转换的合法性。不幸的是，这意味着我们通常必须手动进行这种转换。

**循环交换**：是交换嵌套循环顺序的过程。内循环中使用的归纳变量切换到外循环，反之亦然。[@lst:Interchange] 展示了交换 `i` 和 `j` 的嵌套循环的示例。此循环交换的主要目的是对多维数组的元素执行顺序内存访问。通过遵循元素在内存中的布局顺序，我们可以改善内存访问的空间局部性，并使我们的代码更有利于缓存。此转换有助于消除内存带宽和内存延迟瓶颈。

Listing: 循环交换

~~~~ {#lst:Interchange .cpp}
for (i = 0; i < N; i++)                 for (j = 0; j < N; j++)
  for (j = 0; j < N; j++)          =>     for (i = 0; i < N; i++)
    a[j][i] += b[j][i] * c[j][i];           a[j][i] += b[j][i] * c[j][i];
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

循环交换仅在循环是*完美嵌套*时才是合法的。完美嵌套循环是指所有语句都在最内层循环中的循环。交换不完美嵌套循环更困难，但仍然可行；查看 [Codee](https://www.codee.com/catalog/glossary-perfect-loop-nesting/)[^1] 目录中的示例。

**循环分块（Tiling）**：此转换的思想是将多维执行范围分割成更小的块（block 或 tile），使每个块适合 CPU 缓存。如果算法使用大多维数组并对其元素执行跨步访问，那么缓存利用率低的可能性很高。每次这样的访问都可能将未来访问请求的数据推出缓存（缓存逐出）。通过将算法划分为更小的多维块，我们确保循环中使用的数据保留在缓存中直到被重用。

在 [@lst:blocking] 所示的示例中，算法在对数组 `b` 执行列优先遍历的同时，对数组 `a` 的元素执行行优先遍历。循环嵌套可以划分为更小的块，以最大化数组 `b` 中元素的重用。

Listing: 循环分块

~~~~ {#lst:blocking .cpp}
// 线性遍历                          // 以 8*8 块遍历
for (int i = 0; i < N; i++)             for (int ii = 0; ii < N; ii+=8)
  for (int j = 0; j < N; j++)    =>      for (int jj = 0; jj < N; jj+=8)
    a[i][j] += b[j][i];                   for (int i = ii; i < ii+8; i++)
                                           for (int j = jj; j < jj+8; j++)
                                            a[i][j] += b[j][i];
                                        // 余数（未显示）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

循环分块是优化通用矩阵乘法（GEMM）算法的广为人知的方法。它增强了内存访问的缓存重用，并改善了内存带宽利用率和内存延迟。

通常，工程师会针对每个 CPU 核心私有的缓存大小（Intel 和 AMD 的 L1 或 L2，Apple 的 L1）优化分块算法。然而，私有缓存的大小在每一代都在变化，因此硬编码块大小带来了自身的挑战。作为替代解决方案，你可以使用[缓存无关](https://en.wikipedia.org/wiki/Cache-oblivious_algorithm)[^2]算法，其目标是在任何大小的缓存上都能合理良好地工作。

**循环融合和分布（Fission）**：当独立的循环在相同范围上迭代且不引用彼此的数据时，可以将它们融合。[@lst:fusion] 展示了循环融合的示例。相反的过程称为循环分布（Fission），当循环被拆分为独立的循环时。

Listing: 循环融合和分布

~~~~ {#lst:fusion .cpp}
for (int i = 0; i < N; i++)             for (int i = 0; i < N; i++) {
  a[i].x = b[i].x;                        a[i].x = b[i].x;
                               =>         a[i].y = b[i].y;
for (int i = 0; i < N; i++)             }
  a[i].y = b[i].y;                      
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

循环融合有助于减少循环开销（类似于循环展开），因为两个循环可以使用相同的归纳变量。此外，循环融合有助于改善内存访问的时间局部性。在 [@lst:fusion] 中，如果结构体的 `x` 和 `y` 成员恰好位于同一缓存行上，最好融合两个循环，因为我们可以避免加载同一缓存行两次。这将减少缓存占用并改善内存带宽利用率。

然而，循环融合并不总是改善性能。有时最好将循环拆分为多遍，预过滤数据，排序和重组它等。通过将大循环分布为多个更小的循环，我们限制了循环每次迭代所需的数据量，并增加了内存访问的时间局部性。这在缓存争用很高的情况下有所帮助，这种情况通常发生在大循环中。循环分布还减少了寄存器压力，因为同样，每次循环迭代中执行的操作更少。此外，将大循环拆分为多个更小的循环可能有利于 CPU 前端的性能，因为指令缓存利用率更好。最后，当分布后，每个小循环可以由编译器进一步单独优化。

**循环展开并压缩（Loop Unroll and Jam）**：要执行此转换，你需要先展开外循环，然后压缩（融合）多个内循环，如 [@lst:unrolljam] 所示。此转换增加了内循环的 ILP（指令级并行性），因为更多独立的指令在内循环内执行。在代码示例中，内循环是一个归约操作，累加数组 `a` 和 `b` 元素之间的差值。当我们以因子 2 展开并压缩循环嵌套时，我们有效地同时执行原始外循环的两个迭代。这通过拥有两个独立的累加器来强调。这打破了初始变体中 `diffs` 上的依赖链。

Listing: 循环展开并压缩

~~~~ {#lst:unrolljam .cpp}
for (int i = 0; i < N; i++)           for (int i = 0; i+1 < N; i+=2)
  for (int j = 0; j < M; j++)           for (int j = 0; j < M; j++) {
    diffs += a[i][j] - b[i][j];   =>      diffs1 += a[i][j]   - b[i][j];
                                          diffs2 += a[i+1][j] - b[i+1][j];
                                        }
                                      diffs = diffs1 + diffs2;
                                      // 余数（未显示）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

只要外循环上没有跨迭代依赖，就可以执行循环展开并压缩，换句话说，内循环的两个迭代可以并行执行。此外，如果内循环的内存在外循环索引（此例中为 `i`）上跨步访问，则此转换才有意义，否则其他转换可能更适用。当内循环的迭代次数很低（例如少于 4 次）时，展开并压缩技术特别有用。通过执行此转换，我们将更多独立操作打包到内循环中，这增加了 ILP。

展开并压缩转换有时对外循环向量化非常有用，在撰写本文时，编译器无法自动执行此操作。在内循环的迭代次数对编译器不可见的情况下，编译器仍然可以向量化原始内循环，希望它将执行足够的迭代以命中向量化代码（更多关于向量化的内容在下一节）。但如果迭代次数很低，程序将使用循环的慢标量版本。通过执行展开并压缩，我们使编译器能够以不同方式向量化代码：现在将内循环中的独立指令"粘合"在一起。此技术也称为超级字级并行（SLP）向量化。

### 发现循环优化机会。{#sec:DiscoverLoopOpts}

正如我们在本节开头所讨论的，编译器将完成优化循环的重工作。你可以指望它们对循环代码进行所有明显的改进，如消除不必要的工作、进行各种窥孔优化等。有时编译器足够聪明，可以自动生成快速版本的循环，但其他时候我们必须进行一些重写来帮助编译器。正如我们之前所说，从编译器的角度来看，合法且自动地进行循环转换是非常困难的。通常，当编译器无法证明转换的合法性时，它必须保守行事。

作为第一步，你可以检查编译器优化报告或检查循环的机器代码[^16]以搜索简单的改进。有时，可以使用用户指令调整编译器转换。有一些编译器 pragma 控制某些转换，如循环向量化、循环展开、循环分布等。有关完整的用户指令列表，请检查编译器手册。

接下来，你应该识别循环中的瓶颈，并根据硬件理论最大值评估性能。自上而下的微架构分析（TMA，参见 [@sec:TMA]）方法和 Roofline 性能模型（[@sec:roofline]）都有助于此。循环的性能受以下一个或多个因素的限制：内存延迟、内存带宽或机器的计算能力。一旦识别出循环中的性能瓶颈，尝试应用我们在前几节中讨论的所需转换。

尽管对于特定的计算问题集有众所周知的优化技术，但循环优化仍然是一种随经验而来的"黑艺术"。我建议你依靠编译器，并在必要时手动转换代码来补充它。最重要的是，保持代码尽可能简单，如果性能收益可以忽略不计，不要引入不合理的复杂更改。
