## 现代系统中的噪声 {#sec:secFairExperiments}

硬件和软件中有许多旨在提高性能的功能，但并非所有功能都具有确定性行为。考虑动态频率缩放（DFS），这是一个允许 CPU 将其频率提高到远高于基本频率的功能，使其运行速度显著加快。DFS 通常也称为*turbo*模式。不幸的是，CPU 不能长时间保持在 turbo 模式，否则可能面临过热的风险。因此一段时间后，它会降低频率以保持在其热限制内。DFS 通常很大程度上取决于当前系统负载和外部因素，如核心温度，这使得预测其对性能测量的影响变得困难。

@fig:FreqScaling 显示了 DFS 可能导致性能变化的典型示例。在我们的场景中，我们在"冷"处理器上连续运行了两次基准测试。[^1] 在第一秒内，基准测试的第一次迭代以 4.4 GHz 的最大 turbo 频率运行，但后来 CPU 不得不将其频率降低到 4 GHz 以下。第二次运行没有提升 CPU 频率的优势，也没有进入 turbo 模式。即使我们运行了完全相同版本的基准测试两次，它们运行的环境也不相同。如你所见，第一次运行比第二次运行快 200 毫秒，这是因为开始时它以更高的 CPU 频率运行。当你在笔记本电脑上对软件进行基准测试时，这种情况经常发生，因为笔记本电脑的散热有限。[^4]

![由动态频率缩放引起的性能变化：第一次运行比第二次快 200 毫秒。](../../img/measurements/FreqScaling.jpg){#fig:FreqScaling width=90%}

频率缩放是硬件功能可能导致测量变化的一个例子，然而，变化也可能来自软件。考虑对 `git status` 命令进行基准测试，该命令访问磁盘上的许多文件。在这种场景中，文件系统在性能中起着重要作用；特别是文件系统缓存。在第一次运行时，文件系统缓存中缺少所需的条目。文件系统缓存无效，我们的 `git status` 命令运行非常慢。然而，第二次文件系统缓存会预热，使其比第一次运行快得多。

你可能正在考虑在测量之前包含一次预运行。这确实有帮助，不幸的是，测量偏差也可能在运行中持续存在。[@Mytkowicz09] 论文证明，UNIX 环境大小（即存储环境变量所需的总字节数）或链接顺序（传递给链接器的目标文件顺序）可能以不可预测的方式影响性能。还有许多其他方式内存布局可能影响性能测量。[^2]

具有一致性能需要以相同的条件运行基准测试的所有迭代。在基准测试的每次运行中实现 100% 一致的结果是不可能的，但也许你可以通过仔细控制环境来接近。消除系统中的不确定性有助于明确定义的、稳定的性能测试，例如微基准测试。

考虑当你实施了代码更改并希望通过基准测试程序的"之前"和"之后"版本来了解相对加速比的情况。在这种场景中，你可以控制系统中的大部分可变性，包括硬件配置、操作系统设置、后台进程等。禁用具有不确定性能影响的功能将帮助你获得更一致和准确的比较。你可以在附录 A 中找到此类功能的示例以及如何禁用它们。此外，还有一些工具可以设置环境以确保基准测试结果具有低方差；其中一个工具是 [temci](https://github.com/parttimenerd/temci)[^14]。

但是，不可能复制完全相同的环境并完全消除偏差：可能存在不同的温度条件、功率传输峰值、意外的系统中断等。追踪系统中所有潜在的噪声和变化源可能是一个永无止境的故事。有时无法实现，例如，当你对大型分布式云服务进行基准测试时。

当你想要度量更改的真实世界性能影响时，你不应该消除系统不确定性行为。是的，这些功能可能导致性能不稳定，但它们旨在提高系统的整体性能。你的应用程序的用户很可能启用了它们以提供更好的性能。因此，当你分析生产应用程序的性能时，你应该尝试复制你正在优化的目标系统配置。向系统引入任何人工调优都会改变你的服务用户在实践中看到的结果。[^3]

[^1]: 冷处理器是指处于空闲模式一段时间的 CPU，允许其冷却温度。
[^2]: [@Curtsinger13] 中介绍了一种启用统计上合理的性能分析的方法。这项工作表明，可以通过在运行时反复随机化代码、堆栈和堆对象的位置来消除来自内存布局的测量偏差。遗憾的是，这些想法没有进一步发展，目前这个项目几乎被放弃了。
[^3]: 禁用不确定性性能功能的另一个缺点是它使基准测试运行时间更长。这在持续集成和持续交付（CI/CD）性能测试中尤为重要，因为整个基准测试套件的运行时间有限制。
[^4]: 请记住，即使运行 Windows 任务管理器或 Linux `top` 程序也会影响测量，因为将激活额外的 CPU 核心并将其分配给它。这可能会影响运行实际基准测试的核心的频率。
[^14]: Temci - [https://github.com/parttimenerd/temci](https://github.com/parttimenerd/temci)。
