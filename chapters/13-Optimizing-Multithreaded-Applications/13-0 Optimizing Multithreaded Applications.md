# 优化多线程应用程序 {#sec:secOptMTApps}

现代 CPU 每年都在获得越来越多的核心。截至 2024 年，你可以购买一个拥有超过 200 个核心的服务器处理器！即使具有 16 个执行线程的笔记本电脑在现在也是相当常见的配置。由于每个 CPU 中有如此多的处理能力，有效利用所有硬件线程变得更具挑战性。为软件做好准备以随着 CPU 核心数量的增长而良好扩展，对于应用程序未来的成功非常重要。

服务器和客户端产品利用并行性的方式存在差异。大多数服务器平台设计用于处理来自大量客户的请求。这些请求通常是相互独立的，因此服务器可以并行处理它们。如果系统上有足够的负载，应用程序本身可以是单线程的，平台利用率仍然会很高。但是，当你将服务器平台用于 HPC 或 AI 计算时；那么你需要你拥有的所有计算能力。另一方面，客户端平台（如笔记本电脑和台式机）具有为单个用户服务的所有资源。在这种情况下，应用程序必须利用所有可用的核心来提供最佳用户体验。在本章中，我们将专注于可以扩展到大量核心的应用程序。

从软件的角度来看，实现并行性有两种主要方式：多进程和多线程。在多进程应用程序中，多个独立进程并发运行。每个进程有自己的内存空间，并通过进程间通信机制（如管道、套接字或共享内存）与其他进程通信。在多线程应用程序中，单个进程包含多个线程，这些线程共享进程的相同内存空间和资源。同一进程内的线程可以更容易地通信和共享数据，因为它们可以直接访问相同的内存空间。但是，线程之间的同步通常更复杂，并且容易出现竞态条件和死锁等问题。在本章中，我们将主要关注多线程应用程序，但是一些技术也可以应用于多进程应用程序。我们将在本章中展示两种类型应用程序的示例。

当谈论面向吞吐量的应用程序时，我们可以区分以下两种类型的应用程序：

* **大规模并行应用程序**。此类应用程序通常随着核心数量的增加而良好扩展。它们被设计为处理大量独立任务。大规模并行程序通常使用分治技术将工作分成较小的任务（也称为*工作线程*）并并行处理它们。此类应用程序的示例包括科学计算、视频渲染、数据分析、AI 等。此类应用程序的主要障碍是共享资源（如内存带宽）的饱和，这可以有效地阻塞进程中的所有工作线程。
* **需要同步的应用程序**。此类应用程序的工作线程共享资源以完成其任务。工作线程相互依赖，这会产生一些线程被阻塞的时期。此类应用程序的示例包括数据库、Web 服务器和其他服务器应用程序。此类应用程序的主要挑战是尽量减少所需的同步并避免共享资源上的争用。

在本章中，我们将探讨如何分析两种类型应用程序的性能。由于这是一本关于底层性能的书，我们不会讨论算法级别的优化，如无锁数据结构，这些在其他书中有很好的介绍。
