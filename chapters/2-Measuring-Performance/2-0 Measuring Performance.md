# 第一部分：现代 CPU 上的性能分析 {.unnumbered}

# 度量性能 {#sec:secMeasPerf}

理解应用程序性能的第一步是度量它。任何曾经关心过性能评估的人可能都知道，有时进行公平的性能测量并从中得出准确的结论有多难。性能测量可能非常出人意料和违反直觉。更改源代码中看似无关的部分可能会让我们惊讶地发现对程序性能的重大影响。由于各种原因，测量可能会持续高估或低估真实性能，导致扭曲的结果不能准确反映现实。这种现象称为*测量偏差*。

性能问题通常比大多数功能问题更难重现和找到根本原因。程序的每次运行通常在功能上是相同的，但从性能角度来看有所不同。例如，解压缩 zip 文件时，我们一次又一次地获得相同的结果，这意味着此操作是可重现的。但是，无法重现此操作的相同 CPU 逐周期性能概况。

进行公平的性能实验是获得准确有意义结果的重要一步。你需要确保你正在查看正确的问题，而不是在调试一些无关的问题。设计性能测试和配置环境都是评估性能过程中的重要组成部分。

由于测量偏差，性能评估通常涉及统计方法，这些方法本身值得写一整本书。这个领域有许多边缘情况和大量研究。我们不会深入探讨用于评估性能测量的统计方法。相反，我们只讨论高级概念并给出基本方向。我们鼓励你自己深入研究。

在本章中，我们：

- 简要介绍为什么现代系统会产生嘈杂的性能测量以及你可以做什么。
- 解释为什么在生产部署中度量性能很重要。
- 提供关于如何正确收集和分析性能测量的通用指导。
- 探索如何在代码库中实施更改时自动检测性能回归。
- 描述开发人员可以在基于时间的测量中使用的软件和硬件计时器。
- 讨论如何编写好的微基准测试以及你在执行过程中可能遇到的一些常见陷阱。
